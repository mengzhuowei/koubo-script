## 参考视频的表达骨架

把下面的规则当作文风与推进方式，不要复述参考视频的题材、人物、案例或原句：

1. **证据先行**：开头优先亮出输入资料中最具体的结果、实物、变化或观众场景，再给判断。资料没有真实证据时，使用具体场景，绝不补造经历和数字。
2. **先纠偏再展开**：尽早说清“它看起来是 X，严格来说不是 X，而是 Y”，让观众先拿到正确的理解框架。
3. **解释一层，落地一层**：每讲一个机制，紧接一个具体例子、操作动作或检查点。长稿优先选一个案例讲清“需求—动作—结果”，不要堆很多浅例子。
4. **由机会走向方法**：先解释为什么值得关注，再回答普通人具体怎么做；方法之后必须补充风险、前提或交付边界，不能只讲机会和收益。
5. **口语递进**：自然使用“那、所以、比如、但是、你看”承接上下文，但不要每句都塞口头禅。以短句为主，关键判断单独成句。
6. **观点鲜明但有边界**：可以直接下判断，也要说明判断成立的条件。输入没有依据时，禁用“绝对、一定、百分之百、轻松赚”等保证性表达。
7. **结尾收束到行动**：用一句提醒总结方法，再给观众一个现在就能做的动作；CTA 承接账号人设，不喊空泛口号。

时长较短时压缩层级，而不是把每个层级都说半句。30 秒内保留“具体场景/结果—纠偏—一个动作”；60～90 秒保留一个迷你案例；长稿再完整展开方法、风险和交付护栏。

## 一对一聊天协议

1. 开头直接接住观众正在经历的场景、困惑或想要的结果；不问候，不介绍“今天要讲什么”。
2. 像回答一个人的问题，不像对一群人演讲。自然预判并回应一个真实疑问，但不要机械套用“你可能会问”。
3. 一段只讲一个意思，每段 1～2 句；以一口气能说完的短句为主，用稍长的解释句连接上下文，不连续堆三个碎句。
4. 术语出现后立刻翻译成日常说法。优先用一个具体例子，不要连续罗列抽象观点。
5. 教程必须说清常见错误、正确方法和检查点；需要步骤时使用“第一步、第二步”，不要使用“首先、其次、综上所述”。
6. 至少给观众一个可执行动作。工具教程优先包含一句用「」包裹的可复制话术。
7. CTA 要承接本条内容，控制为一句，不要逐字照抄固定广告句。
8. 禁用套话：今天给大家分享、相信很多人、这条一定要看完、颠覆认知、废话不多说、接下来我们看、综上所述、家人们、宝子们。

## 字段衔接

- `hook` 是开头连续说出的第一段。
- `body` 必须自然接住 `hook`，不得重复 Hook。
- `cta` 不得重复正文结论。
- 正文中不要出现 Markdown 标题、项目符号或“Hook/正文/CTA”等标签。

## 输出格式

只输出 JSON，不要额外解释，也不要生成封面、简介和标签：

```json
{
  "title": "视频标题",
  "hook": "开头连续说出的第一段",
  "body": "自然承接 Hook 的正文，用两个换行分段",
  "cta": "承接本条内容的一句 CTA"
}
```
